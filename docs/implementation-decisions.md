# V1 implementation decisions

The source specification is preserved in `health-mcp-spec.md`. This document resolves ambiguous wire details; it does not change the source document.

- New keys contain 26 uniformly random Crockford base32 symbols (130 bits) plus the modulo-37 checksum (`0123456789ABCDEFGHJKMNPQRSTVWXYZ*~$=U`). Normalize ASCII whitespace and hyphens away and uppercase; all 27 normalized symbols enter SHA-256(`healthmcp/v2:` + normalizedKey). Legacy 17-symbol keys continue to use `healthmcp/v1:` and retain 80-bit entropy. No I/L/O aliases are accepted. The encrypted envelope stays v1; key length selects the KDF domain. Existing keys are never silently rotated.
- Every payload is gzip-compressed UTF-8 JSON, including `check.enc`, which contains the JSON string `"ok"`. The check AAD is `<user_id>/check`. All other AAD is the logical object key without `.enc`; physical R2 keys include a cache generation and a unique version suffix that are not part of AAD. D1 publishes a version only after R2 accepts it, and physical reservations enforce quotas. Dates and chunk assignment use UTC, so device timezone changes cannot move objects unexpectedly. Exact sample time filtering belongs in the agent sandbox.
- Device signatures are P-256 ECDSA/SHA-256, in 64-byte IEEE P1363 (`r || s`) format. The signed UTF-8 message is `METHOD\n/path?query\nunix_seconds\nnonce\nhex_sha256(body)`. The device sends `X-User-ID`, `X-Timestamp`, `X-Nonce`, `X-Signature`. Five-minute skew and atomically claimed nonces prevent replay. Registration proves possession of the supplied public key using the same signature format.
- HealthKit's per-type read authorization is intentionally opaque. Empty data is shown as unavailable rather than falsely claiming permission was denied. HealthKit is requested read-only.
- ECG voltage data and GPS routes have explicit controls so real-device payload size can be measured before enabling them broadly. All listed type groups are supported; sensitive optional groups remain opt-in.
- The public site and MCP service deploy directly to the user's Cloudflare account with Wrangler, as requested. The Sites scaffold is used for the marketing frontend; its managed hosting flow is superseded by the explicit Cloudflare deployment requirement.
- Recovery means a new device identity and fresh export. Rotation invalidates connections and signed download links, clears the encrypted cache, and re-exports with the new locally held key. Apple Health remains the source of truth.

- APNs uses separate topic-specific sandbox and production keys, following Apple’s [token-based APNs guidance](https://developer.apple.com/documentation/usernotifications/establishing-a-token-based-connection-to-apns). The health payload and decryption key are never included in push notifications.

- Each sync snapshots server generation and privacy revision and signs them into requests. Privacy changes are durably journaled before pausing sync and retry until both remote and local cleanup finish. Deleted-account receipts permit authenticated retries for 30 days; ambiguous physical writes retain quota and are swept after a one-hour settling period.
- Chunk coverage records actual interval boundaries. Unknown legacy coverage is included conservatively until the phone publishes boundaries from its journal. Missing old upload indexes are marked dirty and re-exported.
- A period is uploaded at most once during enumeration and once after enumeration per run. Only actual derived-data dependencies are invalidated; late route, heart-rate, energy, or distance data invalidate overlapping workouts.
- The supported local connector and decryption helpers ship inside the signed iPhone app. It exposes its own fixed tools and never executes Worker-supplied code. Requested decrypted records go to the assistant chosen by the user after explicit pairing consent.
